# Settings: costs and rules

Turns estimated profit into confirmed profit. All endpoints are tenant-scoped and need a session.

| Endpoint                                                                                                                                                        | Purpose                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/settings/costs`                                                                                                                                    | Variants with their cost state (entered by you, Shopify estimate, missing), units sold in 90 days, filter, search, sort, paging, catalogue totals.                                                                                        |
| `PUT /api/v1/settings/costs/:variantId`                                                                                                                         | Set a cost from a date. A cost for the same date replaces the earlier one, which stays in history.                                                                                                                                        |
| `GET /api/v1/settings/costs/export`, `POST /costs/import`, `POST /costs/bulk`                                                                                   | Export product costs as CSV, import them (matched by variant id, then SKU), or set one cost on a vendor, product, collection, or list of SKUs.                                                                                            |
| `GET /api/v1/settings/costs/:variantId/history`                                                                                                                 | Every cost ever entered for the variant.                                                                                                                                                                                                  |
| `DELETE /api/v1/settings/costs/entry/:id`                                                                                                                       | Remove a cost (kept in history).                                                                                                                                                                                                          |
| `GET /api/v1/settings/rules`, `POST/DELETE fee-rules`, `POST/DELETE shipping-rules`, `GET shipping-rules/export`, `POST shipping-rules/import`, `PUT threshold` | Payment fee rules (percent plus fixed, per gateway or all), shipping cost rules (flat, per kilogram, or percent of shipping charged; optional country and weight band; CSV import replaces the active rules), missing-cost warning limit. |
| `POST /api/v1/settings/recalculate`                                                                                                                             | `fill_gaps` or `everything`.                                                                                                                                                                                                              |
| `GET /api/v1/settings/audit`                                                                                                                                    | Change history in plain sentences.                                                                                                                                                                                                        |
| `GET /api/v1/settings/currency`                                                                                                                                 | Store currency, shop time zone, ECB rate source, latest rate date, rounding, and a plain explanation of the conversion rule. Display only: Shopify sets the currency and time zone.                                                       |

## Behaviour

- Costs and rules apply from the date chosen. Dates cannot be in the future or before 2000. Amounts are plain decimals (up to 4 places), percentages 0 to 100.
- Saving a cost or rule does not change past orders by itself. **Apply to existing orders** (`fill_gaps`) prices orders whose cost was missing and applies fee and shipping rules; costs already used on past orders stay. **Recalculate everything** (`everything`) also redoes those costs, can change figures already seen, needs a second confirmation in the UI and is written to the audit trail.
- The shop is always taken from the session token; no shop or tenant id is accepted from the client. A cost, rule or audit row of another shop is never readable or removable (404).
- **Currency** shows the store currency and the shop time zone from the shop record. It does not save a change. Rates come from the stored European Central Bank reference rates (the newest date, or none). A latest rate more than 7 days before the shop's business today is marked estimated, the same window the conversion uses. Rounding is half up to that currency's minor unit. Expense categories on this tab are the same create and archive actions as the Expenses screen, and those actions are still written to the audit log. A new expense starts as recurring and monthly; that default is not a separate saved setting. Category class is not stored yet.
- Every change records who (Shopify user id from the session token), what, old and new value.
- Gift cards cannot have a cost.

Code: `packages/db/src/settings.ts` (queries), `packages/db/src/profit.ts` (writes, audit), `apps/api/src/settings/`, `apps/web/components/settings/`.
The original sample-data design is kept at `/dev/settings-design` (development only).

## Rule coverage, previews and recalculation results

- `GET /settings/rules/coverage` shows how the saved rules cover the last 90 days of counted orders (up to 1,000): per gateway, payments with a fee Shopify reported, priced by a rule, or with no fee data; and for orders that ship, how many have a shipping rule, no destination country, or an item with no weight. `POST /settings/fee-rules/preview` and `/shipping-rules/preview` take a rule that is not saved and say how many payments or orders it would be chosen for (`candidateApplies`), so a rule that matches nothing is visible. They use the same selection as the profit calculation (`ruleCoverage`, `packages/profit-engine/src/coverage.ts`) and change nothing.
- A recalculation the merchant starts (`requestedBy: 'merchant'`) records its outcome in the audit log as `profit.recalculated`: orders read, orders changed, orders that had something missing and are now complete, counted orders still incomplete, and contribution profit before and after. `GET /settings/recalculate/last` returns the latest; Settings, Data shows it when the run finishes. Runs started by a sync or webhook are not recorded.
- The CSV import previews (costs and shipping rules) list every problem line (up to 200), and the page offers a downloadable summary file.
